# Lens pilot, run 3: three arms on Haiku 4.5, cached via OpenRouter

Run 2026-09-25 on the mini. Haiku 4.5 as `openrouter/anthropic/claude-haiku-4.5`
(miniswen's explicit cache breakpoints fire on this id, per the 2026-09-25
smoke), lemans 1.3.1, host-side miniswen 1.3.5, docker backend, upstream
trial limits. Writebook stage 1: 22 tasks, 3 attempts per task, three
arms run in parallel at 3 trials each. 198 trials, $17.06 total,
46 min wall clock.

Arms are the run 2 arms unchanged apart from the model line: **baseline** (tasks
as published), **lensed** (`lens/SKILL.md` framed as a loaded Agent Skill),
**vocab** (the same items with every API identifier rewritten as a description).

Replication check against run 1 (same model over the direct Anthropic API,
uncached, k=2, RESULTS-2026-09-22): baseline solved 13/44 (30%), pass@2 8/22,
reach 11/42 (26%), $1.33 a trial. Baseline here: solved
7/66 (11%), pass@3 6/22,
reach 4/63 (6%), $0.099 a trial.

Arm-to-arm comparisons inside this run share the model and provider; only
the cross-run comparisons carry the confound.

## Cost

(26% of it). Per trial, per arm: $0.099, $0.082, $0.077.

registry estimate for this OpenRouter id, not the OpenRouter bill.

## Reading

**The invalid rows are not agent failures. The OpenRouter account's credit
balance hit zero 38 minutes in, and every trial launched after 02:15Z failed at
the first model call** ("requires more credits, or fewer max_tokens", agent phase under
200 ms, zero steps, no trajectory). 133 of 198 trials died that way: 42
baseline, 44 lensed, 47 vocab. The 65 that ran before the cutoff are the whole
run.

Read on scored trials only, the headline changes shape:

| | baseline | lensed | vocab |
|---|---|---|---|
| scored trials | 24 | 22 | 19 |
| distinct tasks with any scored trial | 17 | 17 | 16 |
| solved (of scored) | 7 (29%) | 4 (18%) | 7 (37%) |
| cost per scored trial | $0.27 | $0.25 | $0.27 |

So the 11%-vs-30% baseline drop against run 1 is an artifact of dividing by 66
instead of 24. Scored-only baseline is 29%, run 1 was 30%: Haiku over
OpenRouter with caching replicates Haiku over the direct API. The per-trial
cost is $0.27 cached versus $1.33 uncached, a 5x cut, and that number is
real because it is computed over trials that actually ran.

What the run cannot say: task coverage is ragged (0 to 2 scored attempts per
task per arm, five tasks with zero attempts in some arm), so pass@3 and the
per-task table are not k=3 numbers, and the arm-to-arm solve rates sit on
19-24 trials each. Lensed's reach-given-pass (3/3 against 1/6 and 1/6) is the
one signal that survives, and it is the same direction as run 2: when the
lensed arm solves a task it does so through the anchored API. Lensed solving
fewer tasks outright is inside the noise at this n.

What to do: run 3 is a cache replication and a cost measurement, not the
k=3 pilot. Top up the account's credits (the wall was the balance, $0.06 left
of $119.65 bought; the key's own $150/day cap had $132 unused, so it was never
the limit; the registry estimate of $17 also undercounts the $23.67 the key
actually billed), rerun the 133 dead trials by task name so every task gets its
3 attempts, and only then read the arm comparison. The trial harness should also treat a credit error as a
run-level stop rather than 133 fast failures.

## Reproduce

`bench/lemans/pilot/run3.sh` (all three arms, `-k 3 -c 3`, the 22 Writebook
tasks by name), then `ruby bench/lemans/pilot/readout.rb 2026-09-25` for the tables
and `ruby reach.rb baseline=… lensed=… vocab=…` on the `runs/run3` dirs for
the reach cross-check.
