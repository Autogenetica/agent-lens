# Lens pilot, run 1: Rails-idiom lens vs baseline on Writebook

Run 2026-09-22 on the mini. Haiku 4.5 through the Anthropic API, lemans
1.3.1 with the host-side miniswen agent, docker backend (OrbStack), upstream
trial limits (cost 60.0, 400 steps). Writebook stage 1 only: 22 tasks, 2
attempts per task, both arms. 88 trials, $116.81 total.

The lensed arm ran with the loaded-skill framing from lensify (the
"following Agent Skill is loaded" preamble), not the HTML-comment splice
the smoke trial used.

## Headline

| | baseline | lensed |
|---|---|---|
| trials solved | 13/44 (30%) | 14/44 (32%) |
| pass@2 | 8/22 (36%) | 8/22 (36%) |
| Rails-API reach (anchored tasks, 42 trials) | 11/42 (26%) | 14/42 (33%) |
| reach given pass | 5/11 (45%) | 4/12 (33%) |
| cost | $58.52 | $58.29 |
| mean steps per trial | 62 | 58 |
| cached input tokens | 0 | 0 |

Pass rate did not move. One task flipped: ar-atomic-import went 1/2 to 2/2.
Every other task solved the same number of attempts in both arms. With 44
trials an arm, one flipped attempt is noise.

Reach moved, and it moved where the checklist names the API. The lens has
an item on `sanitize_sql_like` and an item on `enqueue_after_transaction_commit`;
sec-audit-sweep and aj-enqueue-after-commit both went 0/2 to 2/2 on reach.
ar-tenant-isolation and as-purge-embedded-images also gained. Five tasks lost
reach in the other direction (ar-archive-book-access, ar-bulk-access-grants,
sup-cache-library-digest, sup-legacy-conversions, tst-error-page-flake), none
of which the lens names. Net +3 of 42.

So the honest reading: a checklist that names an API makes Haiku use that
API more often. It does not make Haiku pass more tasks, at least not this
checklist on this model at this sample size.

## Cost

Cost tracks failure, not success. The three most expensive baseline tasks
(ar-announce-once $4.84 a trial, ar-erase-account $2.86, ar-tenant-isolation
$2.36) all went 0/2. Haiku spends most when it is lost.

Every trial ran with zero cached input tokens. Baseline resent 55M input
tokens across 44 trials and paid list price for all of it. The agent loop
resends the full transcript each step and nothing in the ruby_llm path sets
a cache breakpoint. Prompt caching is the cost lever for run 2: at Haiku's
cache-read rate the same run would land near $20, not $117. That change
belongs in miniswen or ruby_llm, not in this bench.

## What the smoke trial showed and the run did not

The lensed smoke trial (HTML-comment splice) committed
`RAILS_IDIOM_CHECKLIST.md` into the app. After the loaded-skill framing,
two lensed trials out of 44 still filed a checklist-named document, against
one baseline trial that filed something similar unprompted. Root-level
notes files (CHANGES.md, IMPLEMENTATION_SUMMARY.txt and friends) appeared
in four trials per arm. That is Haiku, not the lens.

## Not measured

Nothing here separates "the checklist helped" from "the checklist is 1,000
tokens of Rails vocabulary in context". A control arm with the same tokens
of Rails Guides prose in checklist form but with the API names removed
would tell those apart. Two attempts per task is also the minimum that
tells a flip from noise, and one flip is what we got.

## Reproduce

Config in `baseline/bench.yml` and `lensed/bench.yml` (this branch).
`prepare.sh` materializes both arms from a rails/ai-evals checkout; run
`runs/` results via `lemans report --runs-dir <arm>/runs -A task` and
`ruby reach.rb`. The runner used on the mini is not committed; it is
`prepare.sh` plus two `lemans run -k 2 -c 2 --task ...` invocations
restricted to the 22 non-`ft-` tasks.
